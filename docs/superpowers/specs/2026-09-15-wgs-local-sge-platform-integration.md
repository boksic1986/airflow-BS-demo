## 1. 修订结论与边界

后台首次启动Local/SGE不需要先在网页创建任务。原生sampleinfo之后，在analysis准备阶段增加可选的平台接入参数；平台自动登记项目，再监控实际执行。网页提交仍保留，不是命令行接入的前置条件。

本修订废止旧设计“首次必须由Airflow启动”“续跑配置必须等于prepare快照”“按批次或目录名识别同一个项目”的前提。项目身份稳定，每次执行内容独立留档。

- WGS仍负责样本筛选、家系/basecount、pending文件交接、rule依赖、Local/SGE profile和qsub。
- 不判断改参影响哪些结果，不自动forceall、不自动选择重算规则。
- 不增加锁系统、资源调度、数据库反写pending、样本改名追踪或离线分析补注册体系。
- CCE Step1–6、GATK、扫描/自动分析、旧运行合同与独立测试项目限制保持不变。
- 不增加面板取消/续跑按钮，不自动接管任意历史目录或未使用接入入口的命令。
- 文档修订之后用户另行授权先修正已有开发；仅隔离源码/BS10610定向验证，不部署、不启动真实任务、不发送WGS开发指令。

## 2. 参数位置与正常流程

建议参数名为 `--platform-monitor`，目前尚未实现/发布；由WGS-pipeline与平台确认后落地，不宣称现在可以执行。

| 阶段 | 原生行为 | 开启监控后的附加动作 |
| --- | --- | --- |
| sampleinfo | 获取样本资料 | 不创建AnalysisRun，不提前创建候选Sample |
| analysis，不加参数 | 原有准备、交接、项目生成 | 不依赖平台，不要求平台账号或token |
| analysis，加接入参数 | 先完成原有准备、交接、项目生成 | 登记项目及准备摘要，保存绑定，显示待启动 |
| 首次执行监控入口 | 运行原生Step1 | 采集最终配置/样本/参数快照，登记execution，再启动与监控 |
| 再次执行监控入口 | 按用户指令续跑 | 同analysis_id，新execution_id/generation与新快照 |

caller、reference和其他参数仍由原生analysis/config管理，平台不维护另一套默认值。prepare完成后允许人工修改配置、样本名、家系信息和实际分析范围。准备摘要仅供预览；配置样本范围按每次执行快照展示，不用该范围推断本次 QC 完成数量。

项目拟提供独立 `Step1_run.monitored.sh`，调用原有 `Step1_run.sh`、透传参数、注入监控；不覆盖原脚本。该入口尚未实现。未启用监控时原操作不变；绕过监控入口的运行不承诺完整前端同步。

### 准备成功但登记失败

项目及原生交接结果保留，报告“准备成功、平台登记失败”。接入层保存不含凭据的稳定项目登记身份，允许对已准备项目单独补登记，不能重跑analysis prepare或pending交接。仅重试在线登记，不建设离线分析补录队列。

回复丢失时使用相同登记身份查询/重试，返回同一个analysis_id。监控启动必须等项目登记和本次execution注册成功；平台不可用时不能静默无监控启动。已经运行后监控失联不应终止分析或自动重投。未启用监控的原生流程不受平台门禁影响。

## 3. 稳定项目身份与目录复用

每个新准备项目生成独立登记UUID；平台登记后绑定analysis_id。绑定记录身份、平台归属和协议版本，不保存凭据，也不能替代认证授权。路径只是当前位置，不是任务唯一键。

| 操作 | 结果 |
| --- | --- |
| A首次登记 | 项目P1、analysis_id R1 |
| A移动/改名为B | 绑定随目录移动；确认后更新R1位置，保留旧位置 |
| 原路径A重新prepare新项目 | 新项目P2、R2；即使批次/样本同名也不复用R1 |
| 原项目改参续跑 | R1不变，新execution；不创建重复项目 |
| 复制目录导致两处携带P1 | 不自动合并或同时接管；明确新分析意图后登记新身份 |

仅在无活动执行时更新位置。旧位置不存在或已绑定另一个P2时，授权调用方凭P1绑定确认新位置；两处仍携带P1则按复制冲突处理，不自动猜测。只核对已知位置，不扫描全盘、不引入设备号/跨主机锁系统。运行中mv可能影响原生流程，本方案不支持活动进程迁移。

日志、rule、配置按analysis_id与execution_id隔离；QC按analysis_id保留一个最新可靠结果。读取项目文件前核对绑定，不能原路径被R2占用后继续替R1读取。历史配置/样本快照独立保存；未采集且丢失的日志显示不可用，不从同名路径补猜。

## 4. 首次与续跑统一使用逐执行快照

同项目保留analysis_id；普通命令行续跑保留平台attempt，新增execution_id及递增generation。不要混淆analysis_id、execution_id、Airflow DagRun ID和WGS原生日志身份。显式新建分析项目才产生新analysis_id；既有网页新attempt逻辑不在本轮重写。

每次启动前保存：

- 当时生效config、其实际引用的样本清单、必要配置引用与内容哈希。
- 实际启动参数、原生入口版本/可验证release来源、mode/target、项目当前位置。
- 平台认证主体、Linux执行账号、analysis_id/attempt/execution_id/generation。
- 启动后追加对应原生日志身份、真实开始/结束与退出结果。

完整样本和配置快照放受控私有存储，独立于可能被移动/复用的项目目录；DB/API只保存必要索引、脱敏摘要和引用。凭据不得进入快照、命令日志、绑定或Git。不复制FASTQ/BAM等大文件。哈希用于当次完整性审计，不要求与prepare或前次执行一致。

采集期间文件改变则拒绝不一致快照，重新采集后才允许启动；不添加通用文件锁。运行期间不应修改配置，平台不能保证这种操作的分析安全和快照准确性。

### 编辑与实际样本范围

2026-09-15按WGS owner对5485c8a源码的核对：范围权威是config.sample中的数据编号集合；sample_info按数据编号关联样本/家系资料，new_sample_info主要用于交付，不用于扩充分析范围。两份实际引用都冻结。元数据表与config.sample缺失/歧义应报错，不重新选择或派生配置；trio/pedigree等一致性仍由用户/原生流程负责。局部target/--until等情况下，配置范围不等于本次实际调度或QC完成分母，后续必须结合execution证据。

启动前/续跑前允许更改算法参数、样本名、家系信息和分析范围。读取config实际引用的清单，不使用prepare旧清单代替，也不只更改UI名称。

仅校验必要字段可解析、引用一致、输入可读、项目归属和执行目标/权限。mode/target与实际入口不符应明确报错，不能静默切换节点或重做prepare。

当前配置样本读取当前execution，历史按对应execution快照保留。人工改名不自动追踪新旧身份，同名样本不跨执行合并。QC保持原生项目最后生成的样本名和内容，不随历史 execution 或人工改名重新关联，不复制成多个 QC，也不冒充本轮重新计算。缺失/不完整读取保留最后可靠结果并标记异常；不以更新当前行覆盖历史配置范围。

**文件交接与执行范围分开：** prepare原始selected/pending记录保留为交接历史，启动时人工修改后的范围是执行事实。监控登记不运行样本选择、不读写pending来作选择，不因改名/删除样本自动取回或放回pending。不能匹配时保留来源不可关联，不能推断交接成功。

平台记录改参，不判断旧结果是否适用、不自动强制重跑；仍由原生WGS和用户的续跑指令决定执行哪些步骤。

## 6. 执行与监控

后台首次启动和命令行续跑都由本地监控入口实际启动；Airflow仅建立对应execution的监控/采集路径，不重复prepare或启动。网页提交保留现有平台启动路径，复用登记/快照与证据消费。

Local在96/97执行；SGE在18运行原生控制进程，由profile投递子任务，不外包一层qsub、不把每个rule建成Airflow task。保留原有资源设置及断点续跑行为。

同一次操作重试复用execution，明确再次续跑才新建execution。同项目有活动执行或无法确定已结束时，阻止重复启动；SGE仅核对关联子任务，不全队列猜测、不自动qdel。旧generation的回调不能覆盖当前状态，observer或监控DAG重启不启动分析。

| 证据 | 页面 |
| --- | --- |
| prepare已登记 | 待启动，准备摘要与执行范围区分 |
| 本次真实启动 | running，排队不算运行时间 |
| 监控失联 | 监控异常，保留最后可靠状态 |
| 本次原生失败证据 | 当前execution失败，保留历史 |
| 原生成功且必要结果可验证 | 采集结果/QC；采集失败不重分析 |

PID消失、qstat消失、qsub返回成功都不能单独证明分析成功。原生WGS_ATTEMPT_ID映射execution/generation；使用本次exitcode/metadata，缺失时间不造值，不伪造CCE完成标记。

复用现有 RunDetail 路由和公共样式；默认当前execution、历史可切换。同analysis_id一条项目记录；配置样本、参数与准确主日志按execution，QC页明确“本 run 最新 QC”且切换历史不改变结果。Rule只采集主日志可定位的事实，不新增原生logger，不从group启动推断子rule时间。Local/SGE隐藏云端OBS/SFS/CCE操作，不新建页面。

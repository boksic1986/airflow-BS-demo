# CCE 0.8.5 release contract

User-approved scope: (1) journal-owned Step6 permission fix, (2) reusable asset
release orchestration, (3) Airflow candidate registration and explicit activation,
(4) inactive by default, retain old assets and frozen attempts. Deliver a wheel.
This task authorizes development/build only, not production installation or activation.

Reuse existing assets validate/apply/status. APPLIED means submitted, never ready.
A bounded wait requires PASS, state_verified=true, exact release ID and manifest
SHA before producing a registration receipt. A resume invocation checks status
first and does not reapply a completed or still-publishing asset transaction.
Do not change prepare, pending, local, SGE, runtime gate, or existing asset commands.
New orchestration refuses destructive replace/delete manifests; operator must use
new frozen profile/asset paths when retaining previous releases. Inactive catalog
does not make in-place SFS writes safe; existing active-Master gates remain binding.

One wire payload (JSON, no secrets), schema_version `cce-release.v1`:
`release`: existing WgsRelease mapping (all existing mandatory fields plus profile_id,
profile_revision, profile_sha256, cce_pipeline_version, node200_profile_path,
pipeline_build_sha256, resource_manifest_sha256 required for managed registration).
`assets`: {release_id, asset_manifest_sha256, profile_id, profile_revision,
profile_sha256, source_commit, pipeline_build_sha256, resource_manifest_sha256,
status: PASS, state_verified: true}. Build SHA is pipeline payload_sha256; resource
SHA is resource files_manifest_sha256. Require both components for managed release.
`release.release_id` is the WGS catalog identity; `assets.release_id` is the CCE
asset transaction identity. They are independent namespaces and need not equal.
Crossbinding compares source_commit, profile_id/revision/SHA, pipeline_build_SHA,
and resource_manifest_SHA, not these two release IDs.
`receipt_sha256`: SHA256 of UTF-8 JSON of the payload without this field, sorted
keys, separators=(',', ':'), ensure_ascii=True. Digest is integrity, not signature.
Only authenticated admins/internal deployment identity may attest deployment.

Endpoints: POST /api/wgs/releases registers this payload, never activates;
GET /api/wgs/releases lists current and candidates without cloud operations;
POST /api/wgs/releases/{release_id}/activate accepts receipt_sha256 and
expected_current_release_id (compare-and-swap). All writes require admin plus
WGS_RELEASE_MANAGEMENT_ENABLED=true AND AUTH_REQUIRED=true. Existing auth/CSRF
or internal-service token contract applies. Activation only changes catalog current;
no attempt, request, queue, configuration options capability, or gate rewriting.
Existing `_refresh_recovery_release` currently auto-upgrades recovery. For CCE
only, resolve/validate the recorded release with by_id and keep params unchanged;
missing/unknown recorded release fails closed. Preserve existing local/SGE branch.
Same ID identical registration is idempotent, changed contents conflict. Keep
schema3/4 reads; atomically upgrade schema3 to4 when registering, preserve raw
unknown metadata and all historical entries. Store receipt beside its release entry
in the same catalog transaction (not a second catalog). Lock sibling file on Linux,
atomic replace with fsync, validate old/new catalog, preserve file permissions.
No arbitrary request-supplied filesystem or network target. Path is deployment setting.
Registration is admin attestation, not a fresh backend Kubernetes probe.

CCE CLI: release publish --operator-config --profile-file --manifest --catalog-entry
--receipt --confirm-publish; produces the receipt after verified assets, optionally
registers when --airflow-url/--token-file given. release register --receipt
--airflow-url --token-file reuses receipt without assets calls. release activate
--release-id --receipt-sha256 --expected-current-release-id --airflow-url --token-file
is separate. Tokens read only from file, never logged/persisted. HTTP requires HTTPS
or loopback HTTP (tests); no credential-forwarding redirects; bounded timeout.
No automatic wheel install, OBS upload, production activation, or old asset cleanup.

Test narrowly: Step6 foreign cache denial/resume; release ready/not-ready/mismatch,
destructive reject, retry without reapply; API authorization/conflict/activation CAS,
legacy preservation and prior release lookup. One synthetic fixed-source producer to
consumer smoke. Build clean source with existing WGS Python on BS10610; isolated
wheel target under WGS_test, metadata/CLI/assets/hash verification. No clinical run.
